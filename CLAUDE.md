# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository structure

This repo is **public** on purpose (the iPad games need it for HTTPS). The nemlig basket tool used to live here but was moved to its own private repo, `mdw-sg/nemlig` (sibling folder `../nemlig`), because it describes the household's shopping habits — don't add personal tools or data here.

This repo contains three fully independent projects — no root `package.json`, no workspaces/turborepo/nx, no shared tooling. Each has its own lockfile and must be installed/run from within its own directory:

- `mobile/` — Expo (React Native) app
- `web/` — Next.js app
- `spil/` — Vite + TypeScript canvas games for the user's 7-year-old son, played on an iPad as a home-screen web app (PWA)

None of the projects has a test framework configured (no Jest, Vitest, or Playwright) — don't assume a `test` script exists or invent test infrastructure without being asked.

## Commands

### mobile/
```
cd mobile
npm install
npm start          # expo start
npm run android     # expo start --android
npm run ios         # expo start --ios
npm run web         # expo start --web (react-native-web)
npm run lint        # expo lint
```
`npm run reset-project` moves the starter code to `app-example/` and creates a blank `app/` — the standard create-expo-app helper, not something to run casually.

### spil/
```
cd spil
npm install
npm run dev         # vite, also reachable on the LAN
npm run build       # tsc + vite build → dist/
```
Pushing changes under `spil/` to `main` deploys it to GitHub Pages (https://mdw-sg.github.io/AI-MAGIC/) via `.github/workflows/spil-pages.yml`.

### web/
```
cd web
npm install
npm run dev         # next dev
npm run build
npm run start
npm run lint         # eslint
```

## Architecture

**mobile/** uses Expo Router (file-based routing) rooted at `mobile/src/app/`. `mobile/src/app/_layout.tsx` is the root layout, wrapping the app in a `ThemeProvider` plus `AnimatedSplashOverlay` and `AppTabs`. Route screens (`index.tsx`, `explore.tsx`) live alongside it. Shared UI is in `mobile/src/components/`, hooks in `mobile/src/hooks/`. Many files have `.web.tsx`/`.web.ts` sibling variants (e.g. `app-tabs.tsx` / `app-tabs.web.tsx`) — these are react-native-web overrides picked up automatically by the bundler for the `expo start --web` target, which is a *separate* web surface from the `web/` project (static output, per `app.json`'s `experiments.output: "static"`). Path aliases: `@/*` → `./src/*`, `@/assets/*` → `./assets/*`.

**web/** is a standard Next.js App Router project. `web/app/layout.tsx` is the root layout (Geist fonts); `web/app/page.tsx` renders the `TicTacToe` component from `web/app/TicTacToe.tsx`. Styling is Tailwind v4. Path alias: `@/*` → repo root of `web/` (not `./src/*`).

**spil/** has no framework: `src/main.ts` drives a `<canvas>` with `requestAnimationFrame`, sound is synthesized with Web Audio, `src/tilt.ts` turns `devicemotion` gravity into steering. `public/sw.js` is a hand-written service worker for offline play. `spil/PLAN.md` holds the agreed game plan and phase status — read it before starting new work and update the status column as phases land. Games must contain no text the child has to read (he can't read yet) — use pictures, icons and spoken Danish. Nothing personal (his name, voice recordings, scores) goes in the repo, since it's public; keep such data in the iPad's browser storage.

## Framework agent-rules files

Both `mobile/` and `web/` have their own `AGENTS.md`/`CLAUDE.md` pairs, generated by their respective framework CLIs — read the relevant one before making framework-level changes:

- `mobile/AGENTS.md`: warns that this Expo SDK version has API changes vs. training data — read the versioned docs at `https://docs.expo.dev/versions/v57.0.0/` before writing code.
- `web/AGENTS.md`: warns that this Next.js version has changes vs. training data — read `node_modules/next/dist/docs/` before writing code. This file is regenerated by `next dev` on every run, so edits to it get overwritten.

## Git workflow

This repo is tracked in Git and pushed to GitHub (`origin` → `github.com/mdw-sg/AI-MAGIC`) so there is always a saved, revertible history. As you do work:

- Commit after each meaningful, working unit of change — don't let edits pile up uncommitted across turns.
- Write clean, specific commit messages describing *why*, not just *what* (e.g. `Add Tic Tac Toe game as web homepage`, not `update files`).
- Push to `origin/main` after committing, so the remote always reflects the latest saved state.
- Keep `mobile/`, `web/` and `spil/` changes in separate commits when a change only touches one of them, since they're independent projects.
