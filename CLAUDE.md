# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository structure

This repo contains three fully independent projects — no root `package.json`, no workspaces/turborepo/nx, no shared tooling. Each has its own lockfile and must be installed/run from within its own directory:

- `mobile/` — Expo (React Native) app
- `web/` — Next.js app
- `nemlig/` — Next.js app (local-only tool that pre-fills the nemlig.com basket from order history)

None of the projects has a test framework configured (no Jest, Vitest, or Playwright test runner; `nemlig/` uses `playwright-core` only to open Chrome for login) — don't assume a `test` script exists or invent test infrastructure without being asked.

## Commands

### mobile/
```
cd mobile
npm install
npm start          # expo start
npm run android     # expo start --android
npm run ios         # expo start --ios
npm run web         # expo start --web (react-native-web)
npm run lint        # expo lint
```
`npm run reset-project` moves the starter code to `app-example/` and creates a blank `app/` — the standard create-expo-app helper, not something to run casually.

### web/
```
cd web
npm install
npm run dev         # next dev
npm run build
npm run start
npm run lint         # eslint
```

### nemlig/
```
cd nemlig
npm install
npm run dev         # next dev on http://localhost:3001, bound to localhost only
npm run lint        # eslint
```

## Architecture

**mobile/** uses Expo Router (file-based routing) rooted at `mobile/src/app/`. `mobile/src/app/_layout.tsx` is the root layout, wrapping the app in a `ThemeProvider` plus `AnimatedSplashOverlay` and `AppTabs`. Route screens (`index.tsx`, `explore.tsx`) live alongside it. Shared UI is in `mobile/src/components/`, hooks in `mobile/src/hooks/`. Many files have `.web.tsx`/`.web.ts` sibling variants (e.g. `app-tabs.tsx` / `app-tabs.web.tsx`) — these are react-native-web overrides picked up automatically by the bundler for the `expo start --web` target, which is a *separate* web surface from the `web/` project (static output, per `app.json`'s `experiments.output: "static"`). Path aliases: `@/*` → `./src/*`, `@/assets/*` → `./assets/*`.

**web/** is a standard Next.js App Router project. `web/app/layout.tsx` is the root layout (Geist fonts); `web/app/page.tsx` renders the `TicTacToe` component from `web/app/TicTacToe.tsx`. Styling is Tailwind v4. Path alias: `@/*` → repo root of `web/` (not `./src/*`).

**nemlig/** is a separate Next.js App Router project, kept apart from `web/` on purpose. It runs only locally on the user's Mac: `app/page.tsx` is the dashboard, `app/api/*` are route handlers, and `lib/` holds the nemlig client and analysis. Security rules that must hold:
- Login happens in a real Chrome window opened by `lib/session.ts`; the code must never fill in or read the login form or listen to page traffic. Only nemlig's cookies are stored.
- Personal data (session, order cache) lives in `~/.nemlig-tool/` (mode 0600), never in the repo, which sits in OneDrive and is pushed to GitHub.
- `lib/client.ts` has an explicit endpoint allowlist; checkout, payment and account endpoints must never be added. The tool never places an order.
- Order data is stripped to product fields in `lib/orders.ts` before saving; addresses, names and phone numbers are dropped.

## Framework agent-rules files

`mobile/`, `web/` and `nemlig/` each have their own `AGENTS.md`/`CLAUDE.md` pairs, generated by their respective framework CLIs — read the relevant one before making framework-level changes:

- `mobile/AGENTS.md`: warns that this Expo SDK version has API changes vs. training data — read the versioned docs at `https://docs.expo.dev/versions/v57.0.0/` before writing code.
- `web/AGENTS.md` and `nemlig/AGENTS.md`: warn that this Next.js version has changes vs. training data — read `node_modules/next/dist/docs/` before writing code. This file is regenerated by `next dev` on every run, so edits to it get overwritten.

## Git workflow

This repo is tracked in Git and pushed to GitHub (`origin` → `github.com/mdw-sg/AI-MAGIC`) so there is always a saved, revertible history. As you do work:

- Commit after each meaningful, working unit of change — don't let edits pile up uncommitted across turns.
- Write clean, specific commit messages describing *why*, not just *what* (e.g. `Add Tic Tac Toe game as web homepage`, not `update files`).
- Push to `origin/main` after committing, so the remote always reflects the latest saved state.
- Keep `mobile/`, `web/` and `nemlig/` changes in separate commits when a change only touches one of them, since they're independent projects.
